# 코드 예제 — MakeCode 붙여넣기 안내

## 파일 구성

| 파일 | 용도 |
|---|---|
| `floor-01.js` ~ `floor-12.js` | 차시별로 **그날 추가하는 코드만** 들어 있다 |
| `all-floors.js` | 12차시 전체 누적본. 연구원 확인용, 진도 따라잡기용 |

수업은 누적 방식이다. 4차시에는 3차시 프로젝트를 열어 `floor-04.js` 내용을 **아래에 이어 붙인다.** 매번 새 프로젝트를 만들지 않는다.

## 붙여넣어 블록으로 바꾸는 순서

1. Minecraft Education에서 `C` 키 → MakeCode 에디터를 연다
2. 새 프로젝트 → 오른쪽 위 **JavaScript** 탭을 누른다
3. 기존 내용을 지우고 코드를 붙여넣는다
4. 다시 **Blocks** 탭으로 전환한다
5. **블록이 전부 컬러로 나오는지 확인한다**

5번이 핵심이다. 회색 `JavaScript` 블록이 섞여 나오면 그 부분은 블록으로 변환되지 않은 것이다. 아이에게 보여줄 수 없으니 문법을 교체해야 한다.

## 블록 변환이 되는 문법 / 안 되는 문법

MakeCode는 JavaScript 전체가 아니라 **static TypeScript** 라는 제한된 문법만 블록으로 되돌린다.

### 쓴다

```ts
let count = 5                              // 변수 선언
count = count + 1                          // 변수 값 바꾸기
for (let i = 0; i < count; i++) { }        // 반복
if (조건) { } else { }                      // 조건
player.onChat("go", function () { })       // 채팅 명령
62 - floor * 4                             // 사칙연산
```

### 안 쓴다

| 문법 | 왜 안 되는가 |
|---|---|
| `const` | 블록에 대응하는 개념이 없다. 전부 `let` 으로 쓴다 |
| `() => { }` 화살표 함수 | 회색 JS 블록이 된다. `function () { }` 로 쓴다 |
| `function myFunc() { }` 사용자 정의 함수 | 이번 프로그램 범위 밖이다 (`context-notes.md` 4장) |
| `[1, 2, 3]` 배열 | 이번 프로그램 범위 밖이다 |
| `{ x: 1 }` 객체 | 변환되지 않는다 |
| `while (true)` | 게임이 멈춘다. `for` 로 횟수를 정한다 |
| `` `${변수}` `` 템플릿 리터럴 | 변환되지 않는다. `player.say(변수)` 를 쓴다 |
| `switch` | 변환되지 않는다. `if / else` 로 쓴다 |

### 방향 상수는 축약형으로 통일한다

MakeCode가 블록에서 생성하는 형태와 같아서 왕복 변환이 안전하다.

```
이동·배치·감지   FORWARD  BACK  LEFT  RIGHT  UP  DOWN
회전            RIGHT_TURN  LEFT_TURN
좌표 방향        NORTH  SOUTH  EAST  WEST
```

`SixDirection.Forward` 같은 긴 형태도 동작하지만, 한 저장소 안에서 두 형태를 섞지 않는다.

## 좌표 관련 주의 (이번 버전에서 새로 들어온 것)

```ts
agent.teleport(world(-12, 58, 8), WEST)
```

- `world(x, y, z)` — **절대 좌표.** 지도 위의 그 지점. 에이전트가 어디 있든 거기로 간다
- `pos(x, y, z)` — **상대 좌표.** 내 위치에서 얼마나 떨어졌는지

둘을 바꿔 쓰면 에이전트가 엉뚱한 곳으로 간다. 이 프로그램은 **전부 `world()`** 를 쓴다.
아이에게는 3차시에서 일부러 둘 다 실행시켜 차이를 보여주면 개념이 한 번에 잡힌다.

`teleport` 의 두 번째 값은 **도착 후 바라볼 방향**이다. 이 방향에 따라 이후 `FORWARD` 가 어느 쪽인지 결정된다. 층마다 방향이 다른 이유는 이동 경로가 층 홀 밖으로 나가지 않게 하기 위해서다.

> **첫 수업 전 확인** — `agent.teleport` + `world()` 는 이번 버전에서 처음 쓰는 API다. 반드시 한 번 실행해 의도한 좌표로 가는지 눈으로 확인한다. `checklist.md` 참고.

## `loops.pause` 를 넣는 이유

에이전트 명령은 실행 요청만 보내고 바로 다음 줄로 넘어간다. 쉬는 시간을 주지 않으면 명령이 밀려서 순서가 꼬이거나 몇 개가 무시된다.

- 이동·설치·파괴 뒤 → `300`
- 슬롯 전환 뒤 → `200`
- 여러 칸 이동이나 텔레포트 뒤 → `400` ~ `700`

아이가 "왜 넣어요?" 라고 물으면 **일부러 지워서 실행시켜 본다.** 명령이 씹히는 걸 직접 보는 게 설명보다 빠르다.
