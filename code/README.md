# 코드 예제 — MakeCode 붙여넣기 안내

## 파일 구성

| 파일 | 용도 |
|---|---|
| `floor-01.js` ~ `floor-12.js` | 차시별로 **그날 추가하는 코드만** 들어 있다 |
| `all-floors.js` | 12차시 전체 누적본. 연구원 확인용, 진도 따라잡기용 |

수업은 누적 방식이다. 4차시에는 3차시 프로젝트를 열어 `floor-04.js` 내용을 **아래에 이어 붙인다.**
**매번 새 프로젝트를 만들면 11·12차시에 통합을 못 한다.**

차시당 명령 4~5개, 코드 56~101줄(주석 제외)이다. 각 차시의 마지막 비필수 명령은 지도안에 **선택**으로 표시돼 있다.

## 붙여넣어 블록으로 바꾸는 순서

1. `C` 키 → MakeCode 에디터 → 새 프로젝트
2. 오른쪽 위 **JavaScript** 탭
3. 기존 내용을 지우고 코드를 붙여넣는다
4. 다시 **Blocks** 탭으로 전환
5. **블록이 전부 컬러로 나오는지 확인한다**

5번이 핵심이다. 회색 `JavaScript` 블록이 섞여 나오면 그 부분은 변환되지 않은 것이다.

## 채팅 명령 매개변수 — 이번 버전의 핵심

```ts
player.onChat("dive", function (num1) {
    let downFloors = num1
    if (downFloors < 1) {
        downFloors = 1
    }
    ...
})
```

채팅창에 `dive 3` 이라고 치면 3이 `num1` 안으로 들어온다. 최대 세 개(`num1` `num2` `num3`)까지 받는다.

**이름을 바꾸지 않는다.** MakeCode가 블록에서 생성하는 이름이 `num1` `num2` `num3` 이다. 다른 이름으로 쓰면 블록 변환이 어긋날 수 있다.

대신 명령 안에서 **곧바로 뜻이 담긴 지역 변수에 옮겨 담는다.** 두 가지 이득이 있다.

- 코드를 읽을 때 그 숫자가 무엇인지 알 수 있다
- 옮겨 담는 그 자리가 **방어 장치를 넣는 자리**가 된다

방어 장치가 필요한 이유는 간단하다. 아이가 숫자 없이 `dive` 만 치면 `num1` 이 0으로 들어와 반복이 한 번도 안 돈다. 2차시에서 **일부러 겪게 한 뒤** 넣는다.

주의 — 명령어와 숫자 사이, 숫자와 숫자 사이에 **띄어쓰기 한 칸**이 필요하다. `dive3` 은 동작하지 않는다.

## 블록 변환이 되는 문법 / 안 되는 문법

### 쓴다

```ts
let count = 5                              // 변수 선언
count = count + 1                          // 누적
for (let i = 0; i < count; i++) { }        // 반복
if (조건) { } else { }                      // 조건
if (num2 == 1) { }                         // 비교
player.onChat("go", function (num1) { })   // 매개변수를 받는 채팅 명령
62 - floor * 4                             // 사칙연산
world(-28 + i * gap, y, 16)                // 좌표 계산
```

### 안 쓴다

| 문법 | 왜 안 되는가 |
|---|---|
| `const` | 블록에 대응 개념이 없다. 전부 `let` |
| `() => { }` | 회색 JS 블록이 된다. `function () { }` |
| `function myFunc() { }` | 이번 프로그램 범위 밖 (`context-notes.md` 4장) |
| `[1, 2, 3]` 배열 | 이번 프로그램 범위 밖 |
| `{ x: 1 }` 객체 | 변환되지 않는다 |
| `while (true)` | 게임이 멈춘다. `for` 로 횟수를 정한다 |
| `` `${변수}` `` | 변환되지 않는다. `player.say(변수)` |
| `switch` | `if / else` 로 |
| `!조건` | 변환은 되지만 쓰지 않는다. `else` 분기로 뒤집는다 |

### 방향 상수는 축약형으로 통일한다

```
이동·배치·감지   FORWARD  BACK  LEFT  RIGHT  UP  DOWN
회전            RIGHT_TURN  LEFT_TURN
좌표 방향        NORTH  SOUTH  EAST  WEST
```

## 층 홀 경계 — 코드를 고칠 때 넘지 말 것

한 층의 열린 공간은 **X −30 ~ 2, Z −14 ~ 24** 다. 그 밖은 돌이다.
개수 × 간격이 이 범위를 넘으면 에이전트가 벽에 박힌다.

관제 홀(X −16~−8, Z 4~12)은 벽으로 둘러싸여 있고 **문은 네 곳뿐**이다.
`(-16, 8)` `(-8, 8)` `(-12, 4)` `(-12, 12)`
좌표를 계산해서 이동하는 명령이 홀을 가로지르면 벽에 막힌다. 6차시 `diag` 가 남서쪽에서 시작하는 이유다.

층별로 비워둬야 하는 미션 동선은 `context-notes.md` 3장 표에 있다.

## 좌표 API 주의

```ts
agent.teleport(world(-12, 58, 8), WEST)
```

- `world(x, y, z)` — **절대 좌표.** 지도 위의 그 지점. 에이전트가 어디 있든 거기로 간다
- `pos(x, y, z)` — **상대 좌표.** 내 위치에서 얼마나 떨어졌는지

이 프로그램은 **전부 `world()`** 를 쓴다. 1차시 `near` 명령만 비교용으로 `pos()` 를 쓴다.

`teleport` 의 두 번째 값은 **도착 후 바라볼 방향**이다. 이후 `FORWARD` 가 어느 쪽인지 결정한다.

> **첫 수업 전 확인** — `agent.teleport` + `world()` 와 `onChat` 매개변수는 1탄에 없던 API다.
> 반드시 실행해서 확인한다. `checklist.md` 참고.

## `loops.pause` 를 넣는 이유

에이전트 명령은 실행 요청만 보내고 바로 다음 줄로 넘어간다. 쉬는 시간이 없으면 명령이 밀려 순서가 꼬인다.

- 설치·파괴·한 칸 이동 뒤 → `200` ~ `250`
- 텔레포트 뒤 → `300` ~ `600`
- 슬롯 전환 뒤 → `200`

아이가 "왜 넣어요?" 라고 물으면 **일부러 지워서 실행시켜 본다.**

이번 버전은 텔레포트를 많이 쓴다. `raft 6 4` 는 24번, `relight 6 11` 은 18번 텔레포트한다. 시간이 오래 걸리면 `pause` 를 낮추기 전에 **범위를 줄여서** 시험한다.
