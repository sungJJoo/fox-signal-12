# 강의 지도안 | 지하 12층 — 신호를 따라서 | 5차시

| 항목 | 내용 |
|---|---|
| 프로그램명 | 지하 12층 — 신호를 따라서 |
| 차시 | 5차시 · 지하 5층 |
| 활동명 | 층 계산기 — 규칙을 코드로 만든다 |
| 운영시간 | 90분 |
| 대상 | 초등 고학년 (5~6학년) |
| 담당 | 박성주 |
| 신호 좌표 | -12 / 42 / -2 |
| 핵심 명령 | `floor` · `sig5` |
| 새로 배우는 것 | 변수끼리 계산하기 |
| 준비물 | 노트북, Minecraft Education, 웹 교재 QR, 4차시 프로젝트 파일 |

> **이 차시가 프로그램 전체의 정점이다.** 아이가 "확장된다"는 말을 몸으로 아는 순간이 오늘 나온다. 시간이 모자라면 다른 활동을 줄이고 ③번을 지킨다.

---

## 오늘의 신호

> **-12 / 42 / -2**
> Z가 처음으로 마이너스로 넘어갔다.
> 그리고 관제실 기록관이 지금까지의 층별 Y를 표로 붙여놓았다.
> **58 · 54 · 50 · 46 · 42 ...**
> "너, 이거 안 보여?"

---

## 목표

- **사고** 층별 Y 값에서 규칙을 찾아내고, 그 규칙을 식으로 표현한다.
- **사고** 표를 외우는 것과 규칙을 계산하는 것의 차이를 안다.
- **결과물** 층 번호 하나만 바꾸면 어느 층이든 가는 `floor` 명령을 만든다.

---

## 흐름

### 도입 · 10분

칠판에 숫자만 쓴다. 설명하지 않는다.

```
1층 → 58
2층 → 54
3층 → 50
4층 → 46
5층 → ?
```

"5층은?" → 42가 바로 나온다. "12층은?" → 여기서 멈칫한다. 하나씩 세어야 하기 때문이다.

> "12층까지 손으로 세면 되긴 해. 근데 100층이면? 규칙을 식으로 쓸 수 있을까?"

### 전개 · 55분

**① 규칙 찾기 (15분) — 코드 없이 종이로**

두 단계로 유도한다.

1. "층이 1 늘 때마다 Y는 몇씩 변해?" → **4씩 줄어든다**
2. "그럼 0층이 있다면 Y는 몇이야?" → 58 + 4 = **62**

여기까지 오면 아이가 식을 만든다.

```
Y = 62 - 층 × 4
```

종이에서 먼저 검산한다. 3층 넣으면 50? 맞다. 12층 넣으면 14? 맞다.
**여기서 12층 Y가 14라는 걸 처음으로 알게 된다.** 이 순간을 크게 짚어준다. 아직 아무도 12층에 가본 적이 없는데 좌표는 이미 알아냈다.

**② 식을 코드로 옮기기 (15분)**

```ts
let targetFloor = 5

player.onChat("floor", function () {
    let depth = 62 - targetFloor * 4
    agent.teleport(world(-12, depth, 8), WEST)
    loops.pause(400)
    player.say(depth)
})
```

Math 블록에서 빼기와 곱하기를 조립한다. 곱하기가 안쪽에 들어가야 한다는 걸 실수로 배우게 둔다.
`62 - targetFloor` 를 먼저 하고 `× 4` 를 하면 결과가 틀린다. 틀린 결과가 나오면 종이 검산과 비교시킨다.

**③ 층 번호만 바꿔 전 층 이동 (20분) — 오늘의 핵심**

`targetFloor` 만 1부터 12까지 바꿔가며 실행한다. 코드 본문은 한 글자도 건드리지 않는다.

| targetFloor | 예상 Y | 실제 Y | 맞음? |
|---|---|---|---|
| 1 | | | |
| 5 | | | |
| 9 | | | |
| 12 | | | |

12를 넣고 실행하면 아직 아무도 안 가본 **지하 12층**에 에이전트가 서 있다. 화면을 다 같이 본다.

> "코드는 그대로인데 층은 열두 개가 됐어. 이게 코드가 확장된다는 뜻이야."

**④ `sig5` 추가 (5분)**
오늘 신호 지점(`-12 / 42 / -2`)으로 가는 명령. Z가 마이너스인 것을 확인시킨다.

### 정리 · 25분

웹 교재 **지하 5층** 페이지에 기록한다.

- `Y = 62 - 층 × 4` 식을 손으로 옮겨 적는다
- 6층부터 12층까지 Y를 **계산해서** 표를 완성한다 (게임으로 확인하지 말고 먼저 계산)
- "코드를 안 고치고 층을 바꿀 수 있었던 이유"를 한 줄로 쓴다

---

## 관찰 포인트

- 규칙을 "4씩 줄어든다"에서 멈추지 않고 **식**으로 만들었는가
- `targetFloor` 를 바꿀 때 코드 본문을 건드리지 않는가
- 12층 Y를 게임보다 **계산으로 먼저** 알아냈는가

## 확장 과제

- 지하 20층이 있다면 Y는? 계산하면 -18이 나온다. 실제로 넣으면 어떻게 되는가. 왜 그런가.
- 층 간격이 4가 아니라 6이라면 식은 어떻게 바뀌는가. 코드에서 4를 6으로 바꿔 확인한다.
- `62` 를 다른 숫자로 바꾸면 무엇이 달라지는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 계산 순서를 틀린다 | `62 - (층 × 4)` 다. 곱하기 블록이 빼기 블록 **안**에 들어가야 한다 |
| Y가 음수로 나온다 | 층 번호가 15를 넘었다. 12까지만 있다는 걸 확인시킨다 |
| `depth` 변수가 안 만들어진다 | `onChat` 안에서 만드는 지역 변수다. Variables에서 만든 뒤 블록을 안쪽에 넣는다 |
| 식은 맞는데 안 움직인다 | `world` 의 Y 자리에 `depth` 변수 블록을 안 끼웠다 |

## 기대효과

- 개별 값을 외우는 대신 규칙을 찾아 일반화하는 사고를 경험한다. 수학의 규칙성 단원과 직접 연결된다.
- 코드를 고치지 않고 값만 바꿔 결과를 확장하는 경험을 하며, 프로그램이 "한 번 만들면 여러 번 쓰는 것"임을 안다.
- 아직 가보지 않은 층의 좌표를 계산으로 먼저 알아내며, 예측이 실제로 맞는 성취를 얻는다.
- 계산 순서를 틀려 결과가 어긋나는 경험을 통해 연산 우선순위를 몸으로 익힌다.
