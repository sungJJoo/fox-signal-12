## 오늘의 신호

> 6층은 조명이 전부 죽어 있다. 화면이 새까맣다.
> 유도등을 심어야 하는데, 아무렇게나 놓으면 안 된다.
> **정확한 간격**으로 놓아야 관제실이 위치를 읽을 수 있다.

## 목표

- **사고** `for` 의 `i` 가 매번 달라지는 값이라는 것을 좌표에 넣어 확인한다.
- **사고** 이동하며 놓는 방식과 좌표를 찍어서 놓는 방식의 차이를 비교해 설명한다.
- **결과물** 개수와 간격을 받아 정확한 좌표에 설치하는 명령 세 개와, 층을 훑는 `drill` 을 만든다.

## 흐름

### 도입 · 10분

1탄에서 만들던 방식을 먼저 실행한다.

```ts
for (let i = 0; i < 5; i++) {
    agent.place(DOWN)
    agent.move(FORWARD, 3)
}
```

> "이거 잘 되지. 그런데 여기서 `i` 는 무슨 일을 했어?"

아무 일도 안 했다. 다섯 번 세기만 했다. 코드 안에서 `i` 를 한 번도 안 썼다.

칠판에 쓴다.

```
i = 0  →  X = -28 + 0 × 3 = -28
i = 1  →  X = -28 + 1 × 3 = -25
i = 2  →  X = -28 + 2 × 3 = -22
```

> "`i` 를 좌표에 곱하면 매번 다른 자리가 나와. 이동 안 하고 바로 그 자리로 보낼 수 있어."

### 전개 · 55분

**① `row` — X 방향 (20분) — 오늘의 핵심**

```ts
player.onChat("row", function (num1, num2) {
    let count = num1
    let gap = num2
    if (count < 1) { count = 1 }
    if (gap < 1) { gap = 1 }
    agent.setSlot(1)
    loops.pause(200)
    for (let i = 0; i < count; i++) {
        agent.teleport(world(-28 + i * gap, 38, 16), WEST)
        loops.pause(350)
        agent.destroy(DOWN)
        loops.pause(250)
        agent.place(DOWN)
        loops.pause(250)
    }
    player.say("가로 설치 완료")
})
```

`row 6 3` 을 치기 **전에** 여섯 개의 X좌표를 종이에 계산해 적게 한다.
실행 후 화면 좌표와 대조한다. 전부 맞으면 오늘 목표는 달성이다.

**두 방식 비교** — 도입에서 만든 이동 방식과 `row` 를 같은 층에서 실행하고 결과를 비교한다.

| | 이동해서 놓기 | 좌표 찍어서 놓기 |
|---|---|---|
| 중간에 벽이 있으면 | | |
| 정확한 위치를 아는가 | | |
| 중간부터 다시 하려면 | | |

이동 방식은 벽에 막히면 뒤가 다 어긋난다. 좌표 방식은 상관없다.

**② `col` — Z 방향 (10분)**
`row` 를 복사해 `i * gap` 을 Z 자리로 옮긴다. 두 글자만 고치면 된다.

**③ `diag` — 두 축에 동시에 (10분)**

```ts
agent.teleport(world(-24 + i, 38, 2 + i), WEST)
```

`i` 를 X와 Z에 함께 쓰면 대각선이 된다.

> "그럼 Y에도 `i` 를 넣으면 계단이 되지 않을까?"

넣어보게 한다. 3~4개까지는 되다가 안 된다. **층 높이가 3칸뿐이기 때문이다.**
아이가 이유를 찾으면 층 구조(바닥 1칸 + 공간 3칸 = 4칸)를 확인시킨다. 5차시 식의 `× 4` 가 여기서 다시 나온다.

**④ `drill` — 층을 훑는다 (15분)**

`i` 로 층 번호를 만들고, 그 층 번호로 다시 Y를 계산한다. **계산이 두 겹이다.**

```ts
for (let i = 0; i < last; i++) {
    let f = i + 1
    let y = 62 - f * 4
    agent.teleport(world(-12, y, 8), WEST)
    loops.pause(600)
    player.say(y)
}
```

`drill 6` → 1층부터 6층까지 순서대로 내려가며 좌표를 보고한다.
채팅창에 58 54 50 46 42 38 이 차례로 찍힌다.

## 관찰 포인트

- 실행 전에 좌표를 계산해서 적는가
- `i` 가 매번 다른 값이라는 걸 자기 말로 설명하는가
- Y에 `i` 를 못 쓰는 이유를 층 구조로 설명하는가
- `drill` 에서 계산이 두 번 일어난다는 걸 짚어내는가

## 확장 과제

- `row` 의 시작 좌표 `-28` 을 변수로 빼면 무엇이 좋아지는가.
- `i * gap` 을 `gap * i` 로 바꾸면 결과가 달라지는가. 왜인가.
- `row` 와 `col` 을 연달아 실행해 십자를 만들려면 시작 좌표를 어떻게 맞춰야 하는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 전부 같은 자리에 놓인다 | `i` 를 좌표에 안 넣었다. 곱하기 블록 안을 확인 |
| 마지막 몇 개가 안 놓인다 | 홀 밖(X < −30)으로 나갔다. `count × gap` 을 계산해본다 |
| 유도등이 안 보인다 | `destroy(DOWN)` 이 빠졌다. 바닥이 이미 차 있다 |
| 에이전트가 블록에 낀다 | Y에 `i` 를 넣었다. 이건 일부러 겪는 실패다 |
| 너무 느리다 | `loops.pause` 를 250으로 낮춘다 |

## 기대효과

- 반복 변수가 단순한 횟수 세기를 넘어 계산의 재료가 된다는 것을 이해한다.
- 상대적 이동과 절대적 지정이라는 두 전략을 비교하고, 상황에 따라 고르는 판단을 시작한다.
- 실행 전에 결과 좌표를 계산해보며 코드를 머릿속에서 돌려보는 습관이 생긴다.
- 계산이 중첩된 구조를 다루며, 5차시의 식이 다른 맥락에서 재사용되는 것을 확인한다.
