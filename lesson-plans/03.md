# 강의 지도안 | 에이전트와 함께해요 2 — 지하 12층 | 3차시

| 항목 | 내용 |
|---|---|
| 차시 | 3차시 · 지하 3층 |
| 활동명 | 좌표를 채팅으로 — 매개변수 두세 개 |
| 운영시간 | 90분 |
| 신호 좌표 | -26 / 50 / 2 |
| 핵심 명령 | `jump` · `warp` · `deck` · `tower` · `sig3` |
| 새로 배우는 것 | `num1` `num2` `num3` |
| 준비물 | 노트북, Minecraft Education, 웹 교재 QR, 2차시 프로젝트, 슬롯 1 → 석재 64개 |

---

## 오늘의 신호

> 3층은 갱도에서 멀리 떨어진 곳에서 신호가 온다.
> 어제 만든 `dive` 로는 아래로만 갈 수 있다.
>
> 좌표는 숫자 세 개다. 세 개를 다 실어 보낼 수 있다면
> **명령 하나로 이 지하 시설 어디든 갈 수 있다.**

---

## 목표

- **사고** 매개변수 개수에 따라 명령의 자유도가 어떻게 달라지는지 비교한다.
- **사고** 하나의 명령이 여러 결과를 만든다는 것을 크기·높이 실험으로 확인한다.
- **결과물** 좌표를 받는 명령 두 개와 크기를 받는 건축 명령 두 개를 만든다.

---

## 흐름

### 도입 · 10분

2차시 `dive` 를 다시 실행한다.

> "`dive` 는 숫자 하나만 받았지. 그럼 두 개, 세 개도 받을 수 있을까?"

`num2`, `num3` 블록을 보여준다. 이미 거기 있었다는 걸 확인시킨다.

> "오늘은 좌표 세 개를 다 채팅으로 넘긴다. 그러면 이 명령 하나가 12층 전체를 커버해."

### 전개 · 55분

**① `jump` — 두 개 (10분)**

3층 안에서만 움직인다. Y는 코드에 고정되어 있다.

```ts
player.onChat("jump", function (num1, num2) {
    agent.teleport(world(num1, 50, num2), WEST)
    loops.pause(400)
    player.say("3층 이동 완료")
})
```

`jump -26 2` 를 친다. 3층 신호 지점에 도착한다.
연구원이 좌표를 불러주고 아이가 **실행 전에** 화면 어디쯤 나타날지 손으로 가리킨다.

**② `warp` — 세 개 (10분)**

```ts
player.onChat("warp", function (num1, num2, num3) {
    agent.teleport(world(num1, num2, num3), WEST)
    loops.pause(400)
    player.say("좌표 투입 완료")
})
```

`warp -12 42 8` → 5층 갱도. `warp -12 14 8` → 12층.
**아직 아무도 안 가본 12층에 오늘 갈 수 있다.** 이 순간을 크게 짚어준다.

> "그럼 `jump` 는 왜 만들었어? `warp` 하나면 되잖아."

3층 안에서만 움직일 때는 Y를 매번 치는 게 오히려 번거롭다는 답이 나오면 좋다.

**③ `deck` — 크기를 받는 건축 (20분)**

1탄의 `box` 와 구조가 같다. 크기만 채팅으로 받는다.

```ts
player.onChat("deck", function (num1) {
    let side = num1
    if (side < 2) {
        side = 2
    }
    agent.setSlot(1)
    loops.pause(200)
    for (let turn = 0; turn < 4; turn++) {
        for (let i = 0; i < side; i++) {
            if (agent.detect(AgentDetection.Block, DOWN)) {
                agent.destroy(DOWN)
                loops.pause(250)
            }
            agent.place(DOWN)
            loops.pause(250)
            agent.move(FORWARD, 1)
            loops.pause(250)
        }
        agent.turn(RIGHT_TURN)
        loops.pause(250)
    }
    player.say(side)
    player.say("발판 완성")
})
```

`deck 4` `deck 6` `deck 9` 를 연달아 친다. 코드는 그대로다.
**실행 전에 필요한 블록 수를 계산하게 한다.** 한 변 × 4다.

**④ `tower` — 높이를 받는 건축 (10분)**
1탄의 `tower` 에 매개변수만 붙인다. `tower 8` `tower 12`.

**⑤ `sig3` (5분)** — 3층 신호 지점 명령.

### 정리 · 25분

웹 교재 **지하 3층** 페이지에 기록한다.

- `warp` 로 가본 층 세 곳의 좌표를 적는다
- `deck` 을 4, 6, 9로 실행했을 때 예상 블록 수와 실제 사용량을 표로 적는다
- `jump` 와 `warp` 중 어느 쪽이 더 편했는지, 언제 그런지 한 줄로 쓴다

---

## 관찰 포인트

- 매개변수 자리와 좌표 자리를 정확히 대응시키는가 (`num1`→X, `num2`→Y, `num3`→Z)
- `deck` 실행 전 필요 블록 수를 계산하는가
- `jump` 와 `warp` 를 상황에 따라 골라 쓰는가

## 확장 과제

- `warp` 에서 `num2`(Y) 자리에 X값을, `num1` 자리에 Y값을 넣으면 어디로 가는가. 왜인가.
- `deck 20` 을 치면 어떻게 되는가. 블록은 몇 개 필요한가. 홀 밖으로 나가는가.
- `tower` 에 `setSlot` 을 빼면 무슨 일이 일어나는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 숫자 두 개를 쳤는데 하나만 먹는다 | 숫자 사이에도 띄어쓰기. `jump -26 2` |
| 벽 속에 끼었다 | 좌표가 홀 밖이다. 홀은 X −30~2, Z −14~24 |
| `deck` 중간에 멈춘다 | 블록이 떨어졌다. 슬롯 1을 64개로 |
| `tower` 가 한 층만 쌓인다 | `move(UP, 1)` 이 안쪽 반복 안에 들어갔다 |

## 기대효과

- 하나의 명령이 입력에 따라 무수히 많은 결과를 만든다는 것을 체감하며 일반화 개념에 닿는다.
- 매개변수 순서와 의미를 대응시키며 위치 정보를 정확히 다루는 훈련을 한다.
- 1탄에서 만든 구조를 그대로 재사용하면서 입력만 바꾸는 경험을 하며 코드 재사용의 가치를 안다.
- 아직 배우지 않은 12층에 좌표만으로 먼저 도달하며, 좌표가 곧 접근 권한이라는 감각을 얻는다.
