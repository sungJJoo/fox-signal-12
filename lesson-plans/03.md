# 강의 지도안 | 지하 12층 — 신호를 따라서 | 3차시

| 항목 | 내용 |
|---|---|
| 프로그램명 | 지하 12층 — 신호를 따라서 |
| 차시 | 3차시 · 지하 3층 |
| 활동명 | 좌표 투입 — 절대 좌표로 직접 보낸다 |
| 운영시간 | 90분 |
| 대상 | 초등 고학년 (5~6학년) |
| 담당 | 박성주 |
| 신호 좌표 | -4 / 50 / 8 |
| 핵심 명령 | `drop` · `home` |
| 새로 배우는 것 | `agent.teleport` + `world(x, y, z)` |
| 준비물 | 노트북, Minecraft Education, 웹 교재 QR, 2차시 프로젝트 파일 |

---

## 오늘의 신호

> **-4 / 50 / 8**
> 3층 신호는 갱도에서 멀리 떨어진 곳에서 온다.
> 걸어서 보내면 몇 분이 걸린다. 관제실에는 더 빠른 방법이 있다.
> **좌표를 직접 찍어서 투입하는 것.**

---

## 목표

- **사고** 절대 좌표(`world`)와 상대 좌표(`pos`)의 차이를 직접 실행해서 구분한다.
- **사고** 좌표 숫자를 바꾸면 에이전트가 어디로 갈지 실행 전에 예측한다.
- **결과물** 신호 지점 투입 명령 `drop` 과 복귀 명령 `home` 을 만든다.

---

## 흐름

### 도입 · 10분

2차시에 예상했던 3층 Y를 확인한다. **50** 이 맞았는지 손들게 한다.

> "그런데 오늘 신호는 X도 Z도 갱도랑 달라. -4랑 8이야.
> `dive` 로는 아래로만 가지. 옆으로 가려면 몇 번을 움직여야 할까?"

세어보게 한다. 갱도는 X가 -12, 신호는 -4. 8칸이다. 귀찮다는 반응이 나오면 성공이다.

### 전개 · 55분

**① `drop` 만들기 (15분)**

```ts
player.onChat("drop", function () {
    agent.teleport(world(-4, 50, 8), WEST)
    loops.pause(400)
    player.say("3층 신호 지점 도착")
})
```

실행 → 에이전트가 순식간에 3층 신호 지점에 나타난다. 화면 좌표로 `-4 / 50 / 8` 을 확인시킨다.

**② `world` 와 `pos` 비교 실험 (20분) — 오늘의 핵심**

같은 코드에서 `world` 만 `pos` 로 바꿔 실행한다.

```ts
agent.teleport(pos(-4, 50, 8), WEST)     // 이렇게 바꿔서 실행
```

에이전트가 전혀 다른 곳으로 간다. 왜인지 물어본다.

- `world(-4, 50, 8)` — **지도 위의 그 지점.** 누가 어디서 실행해도 같은 곳
- `pos(-4, 50, 8)` — **내 위치에서 그만큼 떨어진 곳.** 내가 움직이면 목적지도 움직인다

확인 방법을 준다. 플레이어가 멀리 이동한 뒤 두 명령을 각각 다시 실행한다. `world` 는 항상 같은 곳, `pos` 는 매번 다른 곳.
실험이 끝나면 반드시 `world` 로 되돌려 놓는다.

**③ `home` 만들기 (10분)**
갱도 입구(`-12 / 58 / 8`)로 복귀하는 명령. 아이가 스스로 좌표를 채운다.

**④ 좌표 예측 게임 (10분)**
연구원이 좌표 세 개를 부르면 아이가 코드에 넣고, **실행 전에** 에이전트가 어디쯤 나타날지 손으로 화면을 가리킨다. 그 다음 실행한다.

### 정리 · 25분

웹 교재 **지하 3층** 페이지에 기록한다.

- `world` 와 `pos` 를 각각 실행했을 때 도착한 좌표를 적는다
- 둘의 차이를 한 문장으로 쓴다
- 4층 신호 좌표 `-20 / 46 / 8` 을 미리 적어둔다

---

## 관찰 포인트

- `world` 와 `pos` 의 차이를 자기 말로 설명하는가 (용어가 아니라 의미로)
- 좌표 숫자를 바꾸기 전에 도착 지점을 예측하는가
- `home` 의 좌표 세 개를 스스로 찾아 넣었는가

## 확장 과제

- Y만 바꿔서 실행하면 어떻게 되는가. X와 Z만 바꾸면?
- 존재하지 않는 좌표(예: Y를 300으로)를 넣으면 에이전트가 어떻게 되는지 실험한다.
- 마지막 값 `WEST` 를 `EAST` 로 바꾸면 무엇이 달라지는가. 도착 위치는? 바라보는 방향은?

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 에이전트가 엉뚱한 곳에 있다 | `pos` 로 되어 있다. `world` 로 바꾼다 |
| 에이전트가 블록 안에 끼었다 | 좌표가 벽 속이다. `home` 으로 복귀시킨다 |
| `world` 블록을 못 찾는다 | Position 카테고리. 블록 이름은 "world x y z" |
| 좌표 부호를 빠뜨린다 | `-12` 를 `12` 로 치면 완전히 반대편이다. 마이너스 확인 |

## 기대효과

- 절대 위치와 상대 위치를 구분하며, 위치를 표현하는 방식이 하나가 아니라는 것을 안다.
- "어디"를 말로 설명하는 대신 숫자로 정확히 지정하는 경험을 한다. 이것이 프로그래밍의 기본 태도다.
- 실행 전 예측 → 실행 → 비교의 흐름이 자리 잡아, 코드를 무작정 돌리지 않게 된다.
