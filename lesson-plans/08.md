## 오늘의 신호

> **-6 / 30 / -10**
> 8층은 물에 잠겼다. 통로도 바닥도 보이지 않는다.
> 부술 것도 없다. 밟을 것을 **만들면서** 가야 한다.

---

## 목표

- **사고** 6층과 8층의 차이(자리가 차 있음 / 비어 있음)를 비교해 `destroy` 가 언제 필요한지 판단한다.
- **사고** 필요한 길이를 먼저 재고 그 숫자를 변수에 넣는 순서로 작업한다.
- **결과물** 길이를 자유롭게 바꿀 수 있는 `bridge` 명령을 만들고, 물을 건너 신호 지점에 도달한다.

## 흐름

### 도입 · 10분

슬롯 1의 글로우스톤을 석재로 바꾼다. 왜 바꾸는지 묻는다. (유도등은 길이 아니라 표시다)

`sig8` 로 8층에 보낸다. 물이 보인다.

> "6층에서는 `destroy` 를 먼저 했지. 여기서도 필요할까?"

예상을 말하게 한 뒤 넘어간다. 답은 전개에서 나온다.

### 전개 · 55분

**① `destroy` 없이 놓아보기 (10분)**

```ts
agent.setSlot(1)
agent.place(DOWN)
```

**된다.** 6층에서는 안 됐는데 여기서는 된다. 왜?
발밑이 돌이 아니라 물이기 때문이다. 물은 블록이 밀어낸다.

> "그러니까 `destroy` 는 항상 필요한 게 아니야. **자리가 차 있을 때만** 필요해."

**② `bridge` 만들기 (15분)**

```ts
let bridgeLength = 10

player.onChat("bridge", function () {
    agent.setSlot(1)
    loops.pause(200)
    for (let i = 0; i < bridgeLength; i++) {
        agent.place(DOWN)
        loops.pause(300)
        agent.move(FORWARD, 1)
        loops.pause(300)
    }
    player.say("안전 통로 완성")
})
```

**③ 재고 나서 코딩하기 (20분) — 오늘의 핵심**

물의 폭을 **직접 재게 한다.** 플레이어가 물 이쪽 끝과 저쪽 끝의 Z좌표를 읽고 빼면 된다.

| 항목 | 값 |
|---|---|
| 물 시작 Z | |
| 물 끝 Z | |
| 필요한 길이 (끝 − 시작) | |

잰 숫자를 `bridgeLength` 에 넣고 딱 한 번에 건넌다. 짐작으로 넣으면 모자라거나 남는다.
**측정 → 계산 → 코드**의 순서를 경험하는 것이 오늘 활동의 목적이다.

**④ 남거나 모자랄 때 (10분)**
일부러 3 모자라게 넣어 실행한다. 물에 빠진다. 3 늘려서 다시 실행한다.
"몇을 더 넣어야 하는지"를 실패한 지점의 좌표로 계산하게 한다.

### 정리 · 25분

웹 교재 **지하 8층** 페이지에 기록한다.

- 측정표를 채운다 (물 시작 Z / 끝 Z / 필요 길이)
- "6층에서는 `destroy` 가 필요했는데 8층에서는 왜 필요 없었나" 한 줄로 답한다
- 완성된 통로 스크린샷을 저장한다 (파일명 `08_이름.png`)

## 관찰 포인트

- `destroy` 가 필요한 경우와 아닌 경우를 조건으로 구분해 말하는가
- 길이를 짐작하지 않고 **좌표로 재서** 정하는가
- 모자랐을 때 얼마를 더해야 하는지 좌표 차이로 계산하는가

## 확장 과제

- 통로 폭을 2칸으로 만들려면 어떻게 해야 하는가. 지금 명령을 두 번 쓰는 방법과 코드를 고치는 방법 중 어느 쪽이 나은가.
- `place(DOWN)` 을 `place(FORWARD)` 로 바꾸면 무엇이 만들어지는가.
- 7층의 `clear` 처럼 `if` 를 넣어 "자리가 차 있으면 부수고 놓기"로 바꿀 수 있는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 에이전트가 물에 잠겨 안 보인다 | 좌표는 계속 나온다. 화면 좌표로 위치를 추적한다 |
| 블록이 물에 떠내려간다 | 석재가 아니라 모래·자갈이 슬롯에 들어 있다 |
| 통로가 끊긴다 | `loops.pause` 부족. 400으로 올린다 |
| 슬롯 1이 여전히 글로우스톤 | 에이전트 인벤토리를 다시 연다 |

## 기대효과

- 눈대중이 아니라 측정한 값으로 계획을 세우는 태도가 생긴다. 좌표가 실용 도구가 된다.
- 같은 명령이 환경에 따라 되기도 하고 안 되기도 하는 이유를 조건으로 설명하게 된다.
- 실패한 지점의 좌표로 부족분을 계산하며, 오류를 정보로 바꾸는 경험을 한다.
- 변수 하나가 결과물의 크기를 결정하는 구조를 다시 확인하며 확장성 개념이 굳는다.
