## 오늘의 신호

> 4층 관제 기록관이 보고서를 반려했다.
>
> "`warp` 로 갔다며. 그런데 `deck` 은 그게 어딘지 몰라. `mark` 도 몰라.
> 명령마다 좌표를 따로 치고 있잖아. 하나라도 틀리면 딴 데다 지어."
>
> 명령이 끝나면 `num1` 은 사라진다. **남는 값이 필요하다.**

---

## 목표

- **사고** 매개변수의 수명(명령 실행 중에만 존재)을 실험으로 확인한다.
- **사고** 여러 명령이 하나의 값을 공유하려면 어디에 두어야 하는지 판단한다.
- **결과물** 좌표를 기억시키는 `set` 과 그 값을 함께 쓰는 명령 네 개를 만든다.

## 흐름

### 도입 · 10분 — 불편을 먼저 겪게 한다

3차시 `warp` 와 `deck` 으로 미션을 준다.

> "4층 신호 지점 `0 / 46 / 20` 에 가서 크기 5짜리 발판을 만들고, 표식도 하나 남겨."

`warp 0 46 20` → `deck 5` → 그 다음 표식을 남기려면 좌표를 또 쳐야 한다.
그리고 "다시 6층 `0 / 38 / 16` 으로" 라고 하면 세 명령에 좌표를 전부 다시 친다.

세 번쯤 시키면 반드시 누군가 숫자 하나를 틀린다. 그 화면을 다 같이 본다.

> "`num1` 은 명령이 끝나면 사라져. 다음 명령은 그걸 못 봐.
> 그럼 명령 **바깥**에 두면 되지 않을까?"

### 전개 · 55분

**① 변수 세 개 만들기 (10분)**

`onChat` **바깥**, 코드 맨 위에 만든다. 여기가 중요하다.

```ts
let targetX = 0
let targetY = 46
let targetZ = 20
```

일부러 `onChat` 안에 만들어보게 한 뒤 다른 명령에서 안 보이는 걸 확인시킨다.

**② `set` 과 `show` (15분)**

```ts
player.onChat("set", function (num1, num2, num3) {
    targetX = num1
    targetY = num2
    targetZ = num3
    player.say("좌표 기억 완료")
})

player.onChat("show", function () {
    player.say(targetX)
    loops.pause(300)
    player.say(targetY)
    loops.pause(300)
    player.say(targetZ)
})
```

`set 0 46 20` 을 친 뒤 `show` 를 친다. **숫자를 안 줬는데 대답한다.** 이게 오늘의 첫 놀라움이다.
다른 명령을 몇 개 실행한 뒤 다시 `show` 를 쳐도 값이 남아 있는 걸 확인한다.

**③ `move` `mark` `home` (20분)**

세 명령 모두 좌표를 안 받는다. 기억한 값을 쓴다.

- `move` — 기억한 좌표로 이동
- `mark` — 기억한 좌표에 색 블록 표식 (슬롯 2)
- `home` — 기억한 **층**의 갱도 입구로. `targetY` 만 쓰고 X, Z는 갱도 값 고정

`set` 한 번 → `move` → `mark` → `home` 을 연달아 실행한다. 좌표를 한 번만 쳤다.

**④ 층 바꿔서 재실행 (5분)**

`set 0 38 16` 한 줄만 치고 `move` `mark` `home` 을 그대로 다시 실행한다.
**고친 곳은 한 군데다.** 도입에서 겪은 불편과 대비시킨다.

**⑤ `ring` (5분, 선택)**

시간이 남으면 만든다. 기억한 좌표를 중심으로 사방 `num1` 칸에 표식 네 개.
`targetX + gap`, `targetX - gap` 처럼 **변수에 계산을 붙이는** 첫 경험이다. 5차시 예고가 된다.

### 정리 · 25분

웹 교재 **지하 4층** 페이지에 기록한다.

- 내가 지은 변수 이름 세 개와 그 이유를 적는다
- `set` 한 번으로 몇 개의 명령이 움직였는지 센다
- `num1` 과 변수의 차이를 한 문장으로 쓴다

---

## 관찰 포인트

- 변수를 `onChat` **바깥**에 만드는가
- `set` 없이 `move` 를 먼저 실행했을 때 어디로 가는지 예측하는가 (처음 값이 남아 있다)
- 층을 바꿀 때 `set` 한 줄만 고치는가

## 확장 과제

- 변수를 `onChat` 안으로 옮기면 어떤 오류가 나는가. 왜인가.
- `set` 을 안 치고 `show` 를 치면 무엇이 나오는가. 그 숫자는 어디서 왔는가.
- `home` 은 `targetY` 만 쓴다. X와 Z는 왜 고정인가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 다른 명령에서 변수가 안 보인다 | `onChat` 안에 만들었다. 맨 위 바깥으로 옮긴다 |
| `set` 을 쳐도 값이 안 바뀐다 | `=` 방향이 반대. `targetX = num1` 이다 |
| 변수 이름에 한글이나 공백 | 영어와 숫자만. 공백 대신 대문자 (`targetX`) |
| `mark` 가 아무것도 안 놓는다 | 슬롯 2가 비었다. 색 블록을 넣는다 |

## 기대효과

- 값의 수명이라는 개념을 실험으로 이해하며, 프로그램에 여러 종류의 저장 공간이 있음을 안다.
- 반복되는 실수의 원인을 자기 부주의가 아니라 코드 구조로 보게 된다.
- 이름을 붙이는 일이 미래의 자신과 동료를 위한 장치임을 경험한다.
- 여러 명령이 하나의 값을 공유하는 구조를 만들며 다음 차시 계산식 도입의 바탕을 마련한다.
