## 오늘의 신호

> 1탄에서 너는 에이전트에게 명령하는 법을 배웠다. 기지를 짓고 광물을 캤다.
> 그때 에이전트는 언제나 네 옆에 있었다.
>
> 그런데 폭스 연구소 지하에서 신호가 올라오기 시작했다.
> 30년 전 봉인된 시설. 기록은 남지 않았다.
>
> 사람은 내려갈 수 없다. **에이전트도 네 옆에 있으면 못 내려간다.**
> 옆이 아니라 좌표로 보내야 한다.

---

## 목표

- **사고** `teleportToPlayer`(1탄)와 `teleport + world`(2탄)의 차이를 실행해서 설명한다.
- **사고** 절대 좌표와 상대 좌표를 구분하고, 플레이어가 움직였을 때의 차이를 예측한다.
- **결과물** 지하 투입 명령 세트 다섯 개를 만들고, 6방향 감지 보고 명령을 완성한다.

## 흐름

### 도입 · 10분

**1탄 코드를 먼저 실행한다.** 아이들이 지난 프로그램에서 만든 `base` 나 `smartbox` 를 그대로 돌려본다.

> "이건 다 할 줄 알지. 근데 하나 물어볼게. 이 명령들, 에이전트가 어디서 시작했어?"

전부 플레이어 옆이다. `teleportToPlayer` 로 시작했으니까.

> "지하 12층은 우리가 못 가. 에이전트가 우리 옆에 오면 거긴 못 가는 거야.
> 오늘은 **내가 없는 곳으로 보내는 법**을 배운다."

### 전개 · 55분

**① `back` 과 `go` 비교 (10분)**

`back`(1탄 방식)과 `go`(절대 좌표)를 나란히 만들어 번갈아 실행한다.

```ts
player.onChat("back", function () {
    agent.teleportToPlayer()
    loops.pause(400)
    player.say("에이전트 소환")
})

player.onChat("go", function () {
    agent.teleport(world(-12, 58, 8), WEST)
    loops.pause(400)
    player.say("갱도 입구 도착")
})
```

`go` 를 실행하면 에이전트가 지하로 사라진다. 화면에서 안 보인다. 이 감각이 중요하다.

**② `near` 로 함정 만들기 (15분) — 오늘의 핵심**

숫자는 똑같고 `world` 만 `pos` 로 바꾼 명령을 하나 더 만든다.

```ts
player.onChat("near", function () {
    agent.teleport(pos(-12, 58, 8), WEST)
    loops.pause(400)
    player.say("상대 좌표 이동")
})
```

**플레이어를 세 군데로 옮겨가며** `go` 와 `near` 를 각각 실행하고 좌표를 적게 한다.

| 내 위치 | `go` 도착 좌표 | `near` 도착 좌표 |
|---|---|---|
| 처음 자리 | | |
| 20칸 이동 후 | | |
| 다시 20칸 이동 후 | | |

`go` 는 세 번 다 같고 `near` 는 세 번 다 다르다. 이걸 표로 보게 하는 게 설명보다 빠르다.

**③ `sig` 추가 (5분)**
1층 신호 지점 `-22 / 58 / 18` 로 가는 명령. 아이가 좌표를 직접 채운다.

**④ `look` — 6방향 감지 보고 (20분)**

1탄의 `see` 는 네 방향이었고 막혔을 때만 말했다. 이번엔 여섯 방향에 `else` 까지 붙인다.

```ts
if (agent.detect(AgentDetection.Block, FORWARD)) {
    player.say("앞 막힘")
} else {
    player.say("앞 열림")
}
```

같은 덩어리를 여섯 번 복사해서 방향만 바꾼다. **복사·수정이 오늘의 손기술이다.** 다 만들면 갱도 안과 홀 한가운데에서 각각 실행해 결과를 비교한다.

**⑤ 정찰 (5분)**
`go` → `look` → `sig` → `look` 순서로 실행하며 갱도와 홀의 차이를 좌표와 감지 결과로 정리한다.

### 정리 · 25분

웹 교재 **지하 1층** 페이지에 기록한다.

- `go` / `near` 비교표 세 줄을 옮긴다
- `world` 와 `pos` 의 차이를 한 문장으로 쓴다
- 갱도와 홀에서 `look` 결과가 어떻게 달랐는지 적는다

## 관찰 포인트

- 1탄 코드를 망설임 없이 실행하는가 (전제 수준 확인)
- `go` 와 `near` 의 차이를 "내가 움직이면 같이 움직인다"로 설명하는가
- `look` 의 여섯 덩어리를 복사해서 방향만 정확히 바꾸는가

## 확장 과제

- `WEST` 를 `EAST` 로 바꾸면 도착 위치가 달라지는가, 바라보는 방향만 달라지는가.
- 없는 좌표(Y를 300)로 보내면 에이전트는 어떻게 되는가. `back` 으로 복구되는가.
- `look` 에 `player.say` 대신 감지된 방향 개수를 세게 하려면 무엇이 더 필요한가. (7차시 예고)

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 에이전트가 사라졌다고 당황한다 | 정상이다. 지하에 있다. `back` 으로 부른다 |
| `world` 블록을 못 찾는다 | Positions 카테고리. 블록 이름은 "world x y z" |
| `pos` 로 갔는데 블록 속에 끼었다 | `back` 으로 복구. 이게 `pos` 를 쓰면 안 되는 이유다 |
| 좌표 부호를 빠뜨린다 | `-12` 를 `12` 로 치면 완전히 반대편이다 |
| `look` 이 너무 길어 헷갈린다 | 첫 덩어리를 완성한 뒤 복사·붙여넣기로 다섯 번 |

## 기대효과

- 1탄에서 만든 것이 그대로 쓰인다는 것을 확인하며, 학습이 이어지고 있다는 감각을 얻는다.
- 절대 위치와 상대 위치를 구분하고, 위치를 표현하는 방식이 하나가 아니라는 것을 안다.
- 같은 숫자가 문맥에 따라 다른 결과를 낸다는 것을 표로 확인하며 코드를 꼼꼼히 읽는 태도가 생긴다.
- 감지 결과에 `else` 를 붙여 두 갈래 보고를 만들며, 조건문의 완전한 형태를 익힌다.
