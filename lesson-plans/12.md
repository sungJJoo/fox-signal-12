## 목표

- **사고** 네 단계 작업을 설계하고, 각 단계가 몇 차시 내용인지 스스로 짚는다.
- **사고** 단계 순서를 바꿨을 때 결과가 왜 달라지는지 설명한다.
- **결과물** 통합 미션 `dive12` 를 완주하고, 매개변수를 가진 자기 루틴을 만들어 발표한다.

## 흐름

### 도입 · 10분

칠판에 두 좌표를 나란히 쓴다.

```
1차시 갱도 입구   -12 / 58 / 8
12차시 신호 지점  -12 / 14 / 8
```

> "뭐가 같아?"

X와 Z가 같다. 신호원은 처음부터 갱도 바로 아래에 있었다.

오늘 할 일 네 줄을 안내한다. **새로 배울 게 없다는 걸 먼저 말한다.**

```
1단계  층 번호로 Y를 계산해 투입        5차시
2단계  막힌 곳을 세며 통로 확보         7차시
3단계  두 반복 변수로 착륙장 채우기      8차시
4단계  i 로 좌표를 계산해 유도등 설치    6차시
```

### 전개 · 55분

**① 종이 설계 (10분)**

코드를 열기 전에 네 단계를 종이에 쓴다. 각 단계 옆에 **어느 차시 코드를 가져올지** 적는다.
이걸 안 하면 처음부터 새로 짜려고 든다.

**② `dive12` 조립 (25분)**

**새로 타이핑하지 않는다.** 이전 차시 명령에서 필요한 덩어리를 복사해 붙인다.

- 1단계 → 5차시 `floor` 의 계산 부분
- 2단계 → 7차시 `count` 의 반복 부분
- 3단계 → 8차시 `raft` 의 이중 반복
- 4단계 → 6차시 `row` 의 좌표 계산

```ts
let missionFloor = 12
let deckW = 5
let deckD = 5
let hit = 0
```

전체 코드는 `code/floor-12.js` 에 있다. 실행에 2~3분 걸린다. 그동안 화면을 다 같이 본다.

**막힌 곳 개수**가 채팅에 찍히고, 착륙장이 채워지고, 유도등이 켜진다.

**③ 순서 바꿔보기 (5분)**

3단계와 2단계를 바꿔 실행한다. 착륙장을 먼저 만들면 통로가 안 뚫린 상태라 위치가 어긋난다.

> "1차시부터 계속 나온 얘기야. **순서가 결과를 만든다.**"

**④ 나만의 관제 루틴 (15분)**

```ts
player.onChat("mine", function (num1, num2) {
    let y = 62 - num1 * 4
    let size = num2
    if (size < 1) { size = 1 }
    agent.teleport(world(-12, y, 8), WEST)
    loops.pause(600)
    player.say("루틴 시작")
    myCount = 0

    // ↓ 여기에 직접 이어붙인다

    player.say("루틴 종료")
    loops.pause(300)
    player.say(myCount)
})
```

규칙 세 가지를 시작 전에 말한다.

1. **층과 크기는 채팅으로 받는다.** 코드에 숫자를 박지 않는다
2. **좌표는 계산으로 만든다.** 손으로 세지 않는다
3. **완성 못 해도 된다.** 무엇을 바꿨고 결과가 어떻게 달라졌는지 기록하면 성공이다

3번을 반드시 먼저 말한다. 완성 압박이 있으면 아무것도 시도하지 않는다.

### 정리 · 25분 — 발표

**발표 (15분)** 한 명당 1분. 세 가지만 말한다.

1. 내 루틴은 무엇을 하는가
2. `num1` 과 `num2` 에 무엇을 넣게 했고, 바꾸면 뭐가 달라지는가
3. 잘 안 된 것은 무엇이었나

**기록 (10분)** 웹 교재 **지하 12층** 페이지에 기록한다.

- 12층 화면을 캡처해 저장한다 (`12_이름.png`)
- 내 루틴 이름과 매개변수, 그 의미를 적는다
- 열두 주 중 가장 기억에 남는 층과 이유를 적는다
- **내 기록 전부 내보내기** 를 눌러 열두 주치 기록 파일을 저장한다

**마지막 장면**

> 12층 안쪽에 오래된 에이전트 한 대가 서 있다.
> 30년 전 이 시설이 봉인될 때 혼자 남겨진 최초의 에이전트다.
>
> 그때는 명령을 코드에 하나하나 박아 넣어야 했다.
> 좌표도, 크기도, 횟수도 전부 손으로 고쳐야 했다.
>
> 신호는 좌표를 보내며 계속 이렇게 말하고 있었다.
>
> **"여기 있어."**

## 관찰 포인트

- 처음부터 짜지 않고 **이전 차시 코드를 찾아 가져오는가**
- 종이 설계를 먼저 하는가
- 자기 루틴에 매개변수를 두는가 (숫자를 박지 않는가)
- 안 된 것을 실패가 아니라 기록거리로 말하는가

## 확장 과제 (수료 후)

- 12층에서 지상까지 되돌아 올라오는 루틴을 만든다.
- `relight` 를 12층까지 늘리고, 층마다 착륙장도 함께 만들게 고친다.
- 자기가 만들고 싶은 13층을 설계한다. 좌표, 상황, 필요한 명령을 종이에 적는다.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 코드가 길어 어디가 어딘지 모른다 | 단계마다 `player.say` 를 넣어 진행 위치를 표시 |
| 중간에 멈춘다 | 블록이 떨어졌다. 슬롯 1·2를 64개로 |
| 실행이 너무 오래 걸린다 | `deckW` `deckD` 를 4로 줄인다 |
| 착륙장이 엉뚱한 데 생긴다 | 2단계에서 이동한 만큼 좌표가 밀렸다. 3단계 좌표를 확인 |
| 아무것도 못 만들겠다고 한다 | `dive12` 에서 `deckW` 하나만 바꿔보게 한다. 그것도 자기 루틴이다 |

## 기대효과

- 열두 차시에 걸쳐 배운 조각을 하나의 흐름으로 통합하며 학습의 누적을 스스로 확인한다.
- 기존 코드를 찾아 재사용하는 방식으로 큰 프로그램을 만들며, 실무에 가까운 작업 방식을 경험한다.
- 자기 코드를 매개변수를 가진 형태로 설계하며, 남이 쓸 수 있는 도구를 만든다는 관점을 얻는다.
- 자기 코드를 말로 설명하면서 이해한 것과 따라 한 것을 구분하게 된다.
- 완성이 아니라 시도와 기록을 성과로 인정받는 경험을 통해 다음에도 도전하는 태도가 남는다.
