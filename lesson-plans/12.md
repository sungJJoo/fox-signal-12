## 오늘의 신호

> **-12 / 14 / 8**
> 마지막 신호가 왔다. X도 Z도 갱도와 똑같다.
> 열두 주 동안 옆으로 옮겨다니며 찾았는데,
> 신호는 **계속 우리 발밑에 있었다.**

---

## 목표

- **사고** 네 단계로 이루어진 작업을 순서대로 설계하고, 순서를 바꾸면 결과가 달라짐을 확인한다.
- **사고** 자기가 만든 루틴을 다른 사람에게 말로 설명한다.
- **결과물** 통합 미션 `dive12` 를 완주하고, 자기만의 관제 루틴 `mine` 을 설계해 발표한다.

---

## 흐름

### 도입 · 10분

12층 좌표를 칠판에 쓴다. **-12 / 14 / 8**

> "1층 갱도 입구 좌표가 뭐였지?" → -12 / 58 / 8
> "X랑 Z가 똑같아. 무슨 뜻일까?"

아이가 알아챈다. 신호원은 처음부터 갱도 바로 아래에 있었다. 열두 주 동안 우리는 옆으로만 찾아다녔다.

오늘 할 일을 네 줄로 안내한다.

```
1단계  12층으로 투입한다          (5차시 계산식)
2단계  무너진 통로를 뚫는다        (7차시 조건 판단)
3단계  착륙 발판을 만든다          (9차시 이중 반복)
4단계  유도등으로 길을 낸다        (6차시 설치, 10차시 슬롯)
```

새로 배울 게 없다는 걸 먼저 말해준다. 오늘은 **잇는 날**이다.

### 전개 · 55분

**① 종이 설계 (10분)**
코드를 열기 전에 네 단계를 종이에 순서대로 쓴다. 각 단계에 몇 차시 것을 쓸 건지도 적는다.

**② `dive12` 조립 (25분)**

```ts
let missionFloor = 12
let deckSize = 5

player.onChat("dive12", function () {
    let missionY = 62 - missionFloor * 4
    agent.teleport(world(-12, missionY, 8), WEST)
    loops.pause(600)
    player.say(missionY)

    for (let i = 0; i < 10; i++) {
        if (agent.detect(AgentDetection.Block, FORWARD)) {
            agent.destroy(FORWARD)
            loops.pause(300)
            agent.collectAll()
            loops.pause(300)
        } else {
            agent.move(FORWARD, 1)
            loops.pause(300)
        }
    }
    player.say("통로 확보")

    agent.setSlot(1)
    loops.pause(200)
    for (let side = 0; side < 4; side++) {
        for (let i = 0; i < deckSize; i++) {
            agent.destroy(DOWN)
            loops.pause(300)
            agent.place(DOWN)
            loops.pause(300)
            agent.move(FORWARD, 1)
            loops.pause(300)
        }
        agent.turn(RIGHT_TURN)
        loops.pause(300)
    }
    player.say("착륙 발판 완성")

    agent.setSlot(2)
    loops.pause(200)
    for (let i = 0; i < 3; i++) {
        agent.destroy(DOWN)
        loops.pause(300)
        agent.place(DOWN)
        loops.pause(300)
        agent.move(FORWARD, 2)
        loops.pause(400)
    }
    player.say("신호원 도달")
})
```

전부 새로 짜지 않는다. **이전 차시 코드를 복사해서 붙인다.** 그래서 코드가 남아 있어야 했다는 걸 짚어준다.

실행에 2~3분 걸린다. 그동안 화면을 다 같이 본다.

**③ 순서 바꿔보기 (5분)**
3단계와 2단계 순서를 바꿔 실행한다. 발판을 먼저 만들면 통로가 안 뚫려서 발판이 엉뚱한 데 생긴다.
**순서가 결과를 만든다.** 프로그램 전체를 관통한 문장을 마지막에 다시 확인한다.

**④ 나만의 관제 루틴 (15분)**

```ts
let myFloor = 1
let mySize = 4

player.onChat("mine", function () {
    let myY = 62 - myFloor * 4
    agent.teleport(world(-12, myY, 8), WEST)
    loops.pause(600)
    player.say("나만의 관제 루틴 시작")

    // ↓ 여기에 직접 이어붙인다

    player.say("루틴 종료")
})
```

규칙 세 가지만 준다.

1. 층은 변수로 정한다
2. 크기나 개수도 변수로 뺀다
3. **완성 못 해도 된다.** 무엇을 바꿨고 결과가 어떻게 달라졌는지 기록하면 성공이다

3번을 시작 전에 반드시 말한다. 완성 압박이 있으면 아무것도 시도하지 않는다.

### 정리 · 25분 — 발표

**발표 (15분)** 한 명당 1분. 세 가지만 말한다.

1. 내 루틴은 무엇을 하는가
2. 어떤 변수를 뒀고 그걸 바꾸면 무엇이 달라지는가
3. 잘 안 된 것은 무엇이었나

**기록 (10분)** 웹 교재 **지하 12층** 페이지에 기록한다.

- 12층에서 찍은 스크린샷 (파일명 `12_이름.png`)
- 내 루틴 이름과 변수 목록
- 열두 주 중에 가장 기억에 남는 층과 그 이유

**마지막 장면**

> 12층 안쪽에 오래된 에이전트 한 대가 서 있다.
> 30년 전 이 시설이 봉인될 때 혼자 남겨진 최초의 에이전트다.
> 신호는 좌표를 보내며 계속 이렇게 말하고 있었다.
>
> **"여기 있어."**

## 관찰 포인트

- 코드를 새로 짜지 않고 이전 차시 것을 **찾아서 가져오는가**
- 단계 순서를 바꿨을 때 결과가 달라지는 이유를 설명하는가
- 발표에서 변수의 역할을 말로 설명하는가
- 안 된 것을 실패가 아니라 기록거리로 말하는가

## 확장 과제 (수료 후 이어서 할 것)

- 12층에서 지상까지 되돌아 올라오는 루틴을 만든다.
- `scan` 을 12층까지로 늘리고, 층마다 표식을 남기게 고친다.
- 자기가 만든 층을 하나 설계한다. 좌표와 상황과 필요한 명령을 종이에 적는다.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 코드가 너무 길어 어디가 어딘지 모른다 | 단계마다 `player.say` 를 넣어 어디까지 갔는지 표시한다 |
| 중간에 멈춘다 | 블록이 떨어졌다. 슬롯 1·2를 64개로 채운다 |
| 실행이 너무 오래 걸린다 | `deckSize` 를 4로 줄인다 |
| 아무것도 못 만들겠다고 한다 | `dive12` 에서 숫자 하나만 바꿔보게 한다. 그것도 자기 루틴이다 |

## 기대효과

- 여러 차시에 걸쳐 배운 조각을 하나의 흐름으로 통합하며, 학습이 누적되었음을 스스로 확인한다.
- 순서가 결과를 결정한다는 원리를 마지막에 다시 검증하며 순차 구조의 의미를 확실히 한다.
- 자기 코드를 말로 설명하면서 이해한 것과 따라 한 것을 구분하게 된다.
- 완성이 아니라 시도와 기록을 성과로 인정받는 경험을 통해, 다음에도 도전하는 태도가 남는다.
- 열두 주간의 결과물이 웹 교재에 누적되어 자기 학습 과정을 눈으로 확인한다.
