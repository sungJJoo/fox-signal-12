## 오늘의 신호

> 7층 통로는 군데군데 무너져 있다.
> 뚫고 지나가는 것은 1탄에서 해봤다. 문제는 그 다음이다.
>
> 관제실은 보고를 받아야 한다. **몇 군데가 막혀 있었는가.**
> 에이전트는 지나갔지만 아무것도 세지 않았다.

---

## 목표

- **사고** 조건이 참일 때마다 변수를 키우면 그것이 개수가 된다는 구조를 이해한다.
- **사고** 같은 구간을 두 번 지나면 결과가 왜 달라지는지 설명한다.
- **결과물** 막힌 곳을 세서 보고하는 `count` 와 열린 방향을 세는 `free` 를 만든다.

## 흐름

### 도입 · 10분

1탄의 `smart` 를 그대로 실행한다. 잘 된다.

> "잘 지나갔지. 그럼 몇 군데가 막혀 있었어?"

아무도 모른다. 코드가 세지 않았기 때문이다. 화면을 보고 있던 아이도 정확히는 모른다.

> "관제실은 숫자로 보고받아야 해. 에이전트가 직접 세게 하자."

칠판에 쓴다.

```
막혔다  →  blocked = blocked + 1
```

4차시에서 배운 변수를, 조건 안에서 쓴다.

### 전개 · 55분

**① `count` (25분) — 오늘의 핵심**

```ts
let blocked = 0
let opened = 0

player.onChat("count", function (num1) {
    let steps = num1
    if (steps < 1) { steps = 1 }
    blocked = 0
    opened = 0
    for (let i = 0; i < steps; i++) {
        if (agent.detect(AgentDetection.Block, FORWARD)) {
            blocked = blocked + 1
            agent.destroy(FORWARD)
            loops.pause(250)
            agent.collectAll()
            loops.pause(250)
        } else {
            opened = opened + 1
        }
        agent.move(FORWARD, 1)
        loops.pause(250)
    }
    player.say("막힌 곳")
    loops.pause(300)
    player.say(blocked)
    loops.pause(300)
    player.say("뚫린 곳")
    loops.pause(300)
    player.say(opened)
})
```

`sig7` 로 7층에 보낸 뒤 `count 12` 를 실행한다. **실행 전에 아이가 화면을 보고 막힌 곳 개수를 예상해 적는다.** 그 다음 실행해서 맞춰본다.

**② 초기화 지우고 두 번 실행 (10분) — 일부러 실패**

맨 앞의 `blocked = 0` 을 지우고 같은 구간에서 두 번 실행한다.
두 번째는 숫자가 계속 커진다. **지난 값이 남아 있기 때문이다.**

> "그럼 왜 두 번째는 막힌 곳이 0으로 나와?"

이미 다 부쉈으니까. 여기서 중요한 걸 짚는다. **`count` 는 한 번만 정확하다.** 두 번째부터는 통로가 이미 뚫려 있다.
`reset` 으로 층을 복구한 뒤 다시 재면 같은 값이 나온다.

**③ `clear` (5분)**
세지 않고 뚫기만 하는 버전. `count` 와 나란히 두고 무엇이 빠졌는지 비교한다.

**④ `free` — 열린 방향 세기 (15분)**

지금 자리에서 네 방향 중 몇 개가 열려 있는지 센다.
1차시 `look` 은 여섯 번 말했다. `free` 는 **숫자 하나**로 답한다.

```ts
if (agent.detect(AgentDetection.Block, FORWARD)) {
    player.say("앞 막힘")
} else {
    opened = opened + 1
}
```

갱도 안(사방이 막힘 → 적게 나옴)과 홀 한가운데(열림 → 많이 나옴)에서 각각 실행해 비교한다.

**⑤ `away` (5분, 선택)**
막히면 부수지 않고 오른쪽으로 돌아 피해 간다. 우회 횟수를 센다.

### 정리 · 25분

웹 교재 **지하 7층** 페이지에 기록한다.

- `count 12` 실행 전 예상값과 실제값을 적는다
- 초기화를 지우고 두 번 실행했을 때 나온 숫자를 적는다
- 같은 구간을 두 번 재면 왜 값이 달라지는지 한 줄로 쓴다
- 갱도와 홀에서 `free` 결과를 각각 적는다

---

## 관찰 포인트

- 실행 전에 개수를 예상하는가
- 초기화가 왜 필요한지 두 번 실행 실험으로 설명하는가
- "두 번째는 이미 뚫려 있어서 다르다"를 스스로 짚어내는가
- `free` 에서 `else` 쪽에 증가를 넣는 것을 이해하는가

## 확장 과제

- `blocked` 와 `opened` 를 더하면 항상 `steps` 와 같은가. 왜인가.
- 막힌 곳이 세 군데 이상이면 "위험"이라고 말하게 하려면 무엇이 필요한가.
- `count` 를 아래 방향(`DOWN`)으로 바꾸면 무엇을 세게 되는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| 항상 0이 나온다 | 증가 블록이 `if` 밖에 있거나 초기화가 보고 직전에 있다 |
| 숫자가 계속 커진다 | 초기화가 빠졌다. 이건 일부러 겪는 실패다 |
| 두 번째 실행이 다르다 | 정상이다. 통로가 이미 뚫렸다. `reset` 으로 복구 |
| `else` 블록이 없다 | `if` 블록 왼쪽 아래 톱니바퀴로 추가 |
| 막힌 곳에서 안 움직인다 | `move` 가 반복 안 마지막에 있어야 한다 |

## 기대효과

- 조건 판단의 결과를 값으로 남기는 구조를 익히며, 프로그램이 관찰 결과를 축적할 수 있음을 안다.
- 초기화의 필요성을 실패로 배우며 프로그램의 상태라는 개념에 처음 닿는다.
- 같은 코드가 환경 변화 때문에 다른 결과를 내는 상황을 만나고, 측정 조건을 통제해야 함을 이해한다.
- 여러 번 말하는 보고에서 숫자 하나로 요약하는 보고로 옮겨가며 정보를 압축하는 감각을 얻는다.
