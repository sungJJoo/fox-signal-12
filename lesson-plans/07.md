## 오늘의 신호

> **-24 / 34 / 20**
> 7층 통로는 군데군데 무너져 있다. 어디가 막혔는지는 내려가 봐야 안다.
> 관제실은 볼 수 없다. 그렇다면 **에이전트가 스스로 판단하게** 해야 한다.

---

## 목표

- **사고** 관제실이 모든 상황을 미리 알 수 없을 때, 판단을 에이전트에게 맡기는 구조가 필요함을 이해한다.
- **사고** 같은 명령이 상황에 따라 다르게 동작하는 것을 두 지점에서 비교해 확인한다.
- **결과물** 막히면 치우고 비었으면 전진하는 `clear` 명령을 만든다.

## 흐름

### 도입 · 10분

`sig7` 로 7층에 보낸다. 통로가 중간중간 막혀 있는 것을 보여준다.

> "여기서 앞으로 12칸 가라고 하면 어떻게 될까?"

`agent.move(FORWARD, 12)` 를 실제로 실행한다. 막힌 곳에서 멈춘다.

> "그럼 12번 다 부수라고 하면?" → 안 막힌 데까지 부순다. 그것도 아니다.
> "막힌 곳에서만 부수고, 뚫린 곳에서는 걸어가게 하려면?"

여기서 `if` 가 필요해진다. 개념을 먼저 설명하지 않고 필요를 먼저 만든다.

### 전개 · 55분

**① `detect` 혼자 써보기 (10분)**

```ts
player.onChat("look", function () {
    if (agent.detect(AgentDetection.Block, FORWARD)) {
        player.say("앞이 막혔다")
    } else {
        player.say("앞이 비었다")
    }
})
```

막힌 곳과 뚫린 곳에서 각각 실행한다. **같은 명령인데 답이 다르다.** 이걸 먼저 확인시킨다.

**② `clear` 만들기 (20분)**

```ts
let steps = 12

player.onChat("clear", function () {
    for (let i = 0; i < steps; i++) {
        if (agent.detect(AgentDetection.Block, FORWARD)) {
            agent.destroy(FORWARD)
            loops.pause(300)
            agent.collectAll()
            loops.pause(300)
        } else {
            agent.move(FORWARD, 1)
            loops.pause(300)
        }
    }
    player.say("통로 확보")
})
```

반복 안에 조건이 들어간 첫 구조다. 블록 조립이 오늘 가장 어려운 부분이니 시간을 넉넉히 준다.

**③ 두 지점에서 비교 실행 (15분)**

- 막힌 구간에서 `clear` → 부수면서 나아간다
- 뚫린 구간에서 `clear` → 그냥 걸어간다

같은 코드, 다른 결과. 이걸 아이 입으로 설명하게 한다.

**④ `collectAll` 이 왜 있는지 (10분)**
`collectAll` 을 지우고 실행해본다. 부순 블록이 바닥에 굴러다닌다. 다시 넣으면 주워 담는다.
부수는 것과 줍는 것은 다른 일이다.

### 정리 · 25분

웹 교재 **지하 7층** 페이지에 기록한다.

- "막힌 곳"과 "뚫린 곳"에서 `clear` 를 실행한 결과를 각각 적는다
- `if` 와 `else` 를 각각 한 문장으로 설명한다
- `steps` 를 12에서 몇으로 바꾸면 신호 지점까지 갈 수 있을지 예상해서 적는다

---

## 관찰 포인트

- 같은 명령이 상황에 따라 다르게 동작한 이유를 `detect` 로 설명하는가
- `if` 안과 `else` 안에 무엇이 들어가야 하는지 스스로 판단하는가
- 반복 안에 조건이 들어간 구조를 블록으로 조립할 수 있는가

## 확장 과제

- `if` 와 `else` 안의 내용을 통째로 바꾸면 어떻게 되는가. 실행 전에 예상한다.
- `FORWARD` 를 `DOWN` 으로 바꾸면 에이전트는 무엇을 확인하게 되는가.
- `steps` 를 30으로 늘리면 어디까지 가는가. 홀 밖으로 나가면 어떻게 되는가.

## 자주 막히는 지점

| 상황 | 대응 |
|---|---|
| `else` 블록이 안 보인다 | `if` 블록 왼쪽 아래 톱니바퀴를 눌러 `else` 를 추가한다 |
| 부수기만 하고 안 움직인다 | `move` 가 `if` 안에 들어갔다. `else` 안이어야 한다 |
| 한 칸도 안 움직인다 | 반복 블록 안에 조건 블록을 안 넣고 밖에 뒀다 |
| 아이템이 안 주워진다 | `collectAll` 이 빠졌거나 `destroy` 앞에 있다 |

## 기대효과

- 정보가 부족한 상황에서 판단을 위임하는 설계를 경험하며, 자동화의 기본 개념에 닿는다.
- 조건에 따라 다른 길로 가는 구조를 이해하고, 순차 실행만이 프로그램의 전부가 아님을 안다.
- 같은 코드가 환경에 따라 다르게 동작하는 것을 확인하며, 코드와 환경의 관계를 인식한다.
- 반복과 조건을 겹쳐 쓰는 첫 경험으로, 이후 통합 미션의 기반을 만든다.
